# ADetect 프로젝트형 자료 수집 MVP 업데이트 계획서

작성일: 2026-09-27 · 상태: **승인·구현 완료 → PRD §0 18차 개정으로 반영됨 (이 문서는 역사적 기록)**. 단, 이 문서의 무료 클라우드 배포 항목은 현재 범위에서 제외되었다(PRD §0-2 10번).

기준: 현재 코드와 PRD §0 17차 개정. 이 문서는 변경 제안이며 현재 PRD를 대체하지 않는다. 승인 후 PRD 18차 개정, README, PROJECT_PLAN을 실제 구현과 함께 갱신한다. 이번 작성에서는 제품 코드·운영 데이터·배포 설정을 변경하지 않는다.

## 1. 권장 방향과 승인 범위

**프로젝트를 만들고, 필요한 자료만 수집하고, 확인한 자료만 내려받는 도구로 전환한다.** 시장·브랜드·크리에이티브·종합분석이라는 단계는 없애되 기존 수집 기능은 재사용한다. 설명되지 않는 분석 점수나 전략 추천보다 원문, 출처, 수집 조건, 날짜, 누락 이유를 우선한다.

개인 PC에서 전체 기능을 먼저 완성하고, 같은 코드를 무료 클라우드에서도 실행할 수 있도록 저장소를 분리한다. 무료 배포 우선 후보는 **Streamlit Community Cloud 비공개 앱 + Supabase Free**다. 실제 브라우저 캡처·지속 저장 검증을 통과해야 배포 가능으로 판정한다. 무료 서버와 무료 외부 API는 별개다.

| 결정 항목 | 이번 계획의 권장안 |
|---|---|
| 관리 단위 | 브랜드와 조사 목적을 묶은 프로젝트 |
| 수집 화면 | 8개 자료 종류 중 선택, 순서·선행 단계 제한 없음 |
| 이미 수집한 항목 | 완료 상태와 날짜 표시, 체크 잠금 없음 |
| 종합분석 | 독립 단계 제거, 선택 자료의 근거 요약만 선택 제공 |
| 다운로드 | 자료 종류·개별 자료·수집 버전을 선택해서 생성 |
| 유료 기능 | 기본 ON, 선택한 기능 실행 때만 호출 |
| 저장 | 결과와 원본·다운로드 파일의 보관 정책 분리 |
| 배포 | 로컬 우선, 무료 클라우드 사전 검증 후 적용 |
| 이용자 | 본인 1명, 클라우드도 비공개 |

수집 항목·보관 수치·배포 후보는 승인할 제안이다. 기존 대화에서 요청한 유료 기본 ON과 정확한 오류 문구는 유지한다. **실계정 유료 테스트는 별도 승인 대상**이며 계획 승인만으로 유료 호출을 하지 않는다.

## 2. 현재 구현에서 바꿔야 하는 지점

현재는 Streamlit, SQLite, 로컬 파일 저장, 4개 자료 탭, 소스별 수집기와 HTML/Excel/ZIP 내보내기가 있다. 다시 만들기보다 실행·저장·선택 구조를 바꾼다.

| 현재 상태/관측 | 개선 |
|---|---|
| 조사 세션별 이력, 프로젝트 없음 | 프로젝트 아래 여러 수집 실행과 다운로드 이력 연결 |
| market/brand/creative 단위 실행 | 8개 자료 종류별 실행·상태·재시도 |
| 유료 OFF·계정 미입력도 실패처럼 보일 수 있음 | 선택 안 함·설정 필요·실패·결과 없음 구분 |
| 화면 필터/제외가 통합 내보내기에 그대로 적용되지 않음 | 명시적 자료 선택 목록으로 내보내기 생성 |
| 한샘 뉴스 400건 중 URL 기준 351개 관측 | 동일 기사 중복 표시 제거, 발견 검색어는 모두 보존 |
| 관련 없는 자료·빈 시트까지 산출물에 포함 | 포함 대상만 출력, 빈 종류별 시트 생략 |
| 최근 실행 복원이 실패 결과로 이전 성공 결과를 가릴 수 있음 | 최근 시도와 최근 성공 자료를 별도로 관리 |
| 파일 용량 제한은 있지만 DB 이력은 계속 증가 | DB·원본·산출물·캐시·이벤트 모두 보관 상한 적용 |
| 실행 중 작업 상태가 프로세스 메모리에 있음 | 진행 상태 저장, 재시작 후 중단 표시 및 선택 재개 |

한샘 관측 수치는 해당 입력과 수집 시점의 표본이다. 전체 뉴스·광고·시장 규모를 뜻하지 않는다.

## 3. 화면과 사용 흐름

상단 메뉴는 **홈 / 프로젝트 / 설정**으로 단순화한다. 이력은 각 프로젝트 안으로 이동하고 기존 이력 링크는 호환 연결한다. 홈의 기존 단일 Hero와 지정 배경은 유지하며 브랜드 입력 후 프로젝트 생성 화면으로 연결한다.

프로젝트 내부는 **자료 수집 / 자료 확인·다운로드 / 이력**으로 구성한다. 프로젝트명·조사 목적·최종 수집일·저장 용량을 상단에 표시한다. 설정 변경은 프로젝트 설정에서 한다.

1. `프로젝트 만들기`: 이름, 브랜드, 조사 목적 입력. 예: `한샘 — 리하우스 조사`.
2. 검색어·공식 페이지·계정 입력. 당장 선택한 자료에 필요한 입력만 필수로 요청한다.
3. `조사에 필요한 자료를 선택하세요`: 각 자료의 설명, 보유 상태, 실행 비용 유형, 수집 한도를 확인한다.
4. `선택 자료 수집`: 선택된 자료만 실행한다. 성공 자료는 즉시 확인하고 실패 자료만 재시도한다.
5. 표에서 검색·필터·일괄 선택·포함/제외 확인 후 다운로드한다.
6. 나중에 프로젝트를 열어 다른 자료를 추가하거나 특정 자료만 새로 수집한다.

처음에는 체크를 비워 두고 `기본 자료 선택` 버튼으로 검색 추이·검색량·뉴스·입력된 공식 페이지를 한 번에 선택하도록 제안한다. 유료 기능 사용 스위치의 기본 ON과 수집 항목 자동 선택은 다른 개념이다. 사용자가 무엇을 실행할지 확인하는 화면은 항상 둔다.

뉴스를 수집했다면 `뉴스 · 351건 · 9/27 수집 · 자료 보기 / 새로 수집`으로 표시한다. 뉴스 체크를 해제해도 저장된 뉴스는 없어지지 않는다. 체크를 잠그면 최신 뉴스 갱신과 부분 재수집이 어려워지므로 잠그지 않는다.

별도 필수 가이드 페이지 대신 화면 상단에 접을 수 있는 `1분 사용법`을 제공한다. Workspace는 장식보다 데이터 가독성을 우선하고, 긴 카드 나열 대신 표·행별 미리보기를 사용한다.

## 4. 선택 가능한 자료 전체 목록

| 선택 항목 | 수집·제공 내용 | 입력/경제성/제한 |
|---|---|---|
| 검색 관심도 추이 | 완료된 최근 36개월 상대지수, 월별 평균, 연도별 피크·저점, 제공 월수 | 선택 검색어, NAVER API. 누락 월을 0으로 채우지 않음 |
| 월간 검색량·연관 검색어 | PC/모바일 제공값, 관련 검색어, 조회 시각 | 선택 검색어, NAVER 검색광고 API. `<10` 보존. 과거 36개월 절대 검색량으로 오인하지 않도록 구분 |
| 관련 뉴스 | 제목, 제공 발췌문, 매체 정보가 있으면 매체, 발행일, 원문 링크, 발견 검색어 | 검색어별 최대 100건 기본, URL 중복 제거. 기사 전문 수집은 제외 |
| 공식 페이지 자료 | 지정 페이지의 텍스트·링크·캡처, 선택 시 이미지 원본 | 직접 확인한 URL. 페이지에 쓰인 주장과 검증된 사실을 구분. 전체 사이트 자동 순회 안 함 |
| 네이버 검색 화면 | 선택 검색어별 화면 캡처, 관측 일시·조건, 원문 링크 | 브라우저 실행 필요. 자동 광고 순위·미운영 판정 없음 |
| Meta 광고 소재 | 제공된 문구·CTA·형식·지면·시작일·랜딩·미디어 | 확인한 페이지, 기본 최대 20건 표본, Apify 유료. 표본을 전체 광고량으로 표현하지 않음 |
| Instagram 공식 계정 | 제공 가능한 프로필·최근 게시물·게시 시각·반응 수·원문 링크 | 확인한 계정, 최근 5건 기본, Apify 유료. 누락 지표 추정 안 함 |
| YouTube 공식 채널 | 채널·최근 영상 제목·게시일·제공 지표·원문 링크 | 확인한 채널, 최근 5건 기본, API 할당량 사용. 영상 원본 다운로드 기본 제외 |

공식 페이지 이미지 저장, 광고 원본 저장, 이전 수집 대비 변경 확인도 MVP에 포함한다. 이미지 OCR·임의 소구 분류·자동 전략·타겟 인구통계·포지셔닝·점유율 추정은 제외한다. 광고 다중 이미지 등 제공된 원본은 가능한 범위에서 보존하되 제한·실패를 명시한다.

검색 추이는 검색어별 상대지수다. 각각의 최고값 100을 같은 절대 검색량으로 비교하지 않는다. 전체 월별 평균 최고·최저는 36개월 제공과 유효한 차이를 확인한 경우만 표시하며, 연도별 표에는 관측 월수를 붙인다. 반복된 월별 패턴은 관측 사실로 설명하고 미래 계절성을 단정하지 않는다.

선택한 최대 20개 자료에 `근거 요약 첨부`를 제공한다. 실행 버튼을 눌렀을 때만 AI를 호출하며 출처·근거·신뢰도와 인용 검증을 유지한다. 사용자가 자료 선택을 바꾸면 기존 요약이 현재 선택과 다르다는 표시를 하고 자동 재호출하지 않는다.

## 5. 검색어 입력과 캠페인 범위

브랜드/캠페인 검색어는 고유 이름, 일반 검색어는 제품·서비스·직무·관심 주제를 뜻한다. 검색량의 비교 대상이 자동으로 정답이 되는 것은 아니므로 사용자가 선택한다. 두 종류 합계 최대 10개 제한을 유지한다.

| 입력 | 한샘 예시 | 메리츠 TM 채용 예시 |
|---|---|---|
| 브랜드 | 한샘 | 메리츠화재 |
| 조사 대상 | 리하우스·리모델링 | TM 채용 캠페인 |
| 브랜드/캠페인 검색어 | 한샘, 한샘 리하우스 | 메리츠화재 TM, 메리츠 TM사관학교 |
| 일반 검색어 | 인테리어, 리모델링 | TM 채용, 보험 상담원 채용 |
| 포함 문구 | 리하우스, 리모델링 | TM사관학교, 채용 |
| 공식 URL/계정 | 조사할 페이지 직접 지정 | 제공받은 채용 랜딩·meritz_tm_school·Meta 페이지 |

화면은 실제 값으로 설명한다. 예: `브랜드/캠페인 검색어: 한샘, 한샘 리하우스를 기준으로 선택한 검색 추이·검색량·뉴스·검색 화면을 수집합니다.` `일반 검색어: 인테리어, 리모델링을 같은 방식으로 조회합니다.` 선택 안 한 자료까지 실행하는 것처럼 설명하지 않는다.

공식 페이지·SNS·Meta는 검색어로 계정을 자동 확정하지 않고 지정 URL/계정을 사용한다. 포함/제외 문구는 기본적으로 수집 후 관련성 확인에 사용하며, API 검색 결과 전체를 캠페인 전용 데이터로 만들지는 않는다. 검색어별 대상 선택을 지원한다. 입력 변경은 다음 실행부터 적용하고 과거 실행의 입력은 그대로 보존한다.

## 6. 프로젝트·실행·상태 데이터

프로젝트 → 입력 버전 → 수집 실행 → 자료 종류별 작업 → 결과·원본 참조 → 다운로드 구성/요청 이력으로 연결한다. 새 결과는 `schema_version=3`으로 구분하고 기존 v2 읽기를 유지한다.

| 데이터 | 저장할 핵심 값 |
|---|---|
| 프로젝트 | ID, 이름, 브랜드, 조사 목적, 생성일, 보관 상태 |
| 입력 버전 | 검색어·대상·URL·계정·포함/제외 조건·옵션의 불변 사본, 비밀키 제외 |
| 실행/작업 | 프로젝트·입력 버전·자료 종류, 요청 ID, 시각, 상태, 시도 횟수, 오류, 외부 작업 ID |
| 자료 | 고유 ID, 출처 URL, 본문/제공 필드, 수집 시각, 발견 검색어 목록, 근거, SAMPLE 여부 |
| 확인 상태 | 자료 버전별 포함/확인 필요/제외 및 수정 시각 |
| 원본 | 내용 해시, 크기, 형식, 저장 위치, 참조 목록, 만료 상태 |
| 다운로드 구성 | 선택 자료/버전, 확인 상태 사본, 포맷·생성기 버전, 생성 시각, 누락 원본, 파일 해시 |
| 다운로드 요청 | 구성 ID, 요청 시각. 브라우저 저장 완료와 구분 |

작업 상태는 `미선택 / 설정 필요 / 대기 / 수집 중 / 완료 / 부분 완료 / 결과 없음 / 실패 / 중단`으로 구분한다. 파일 보관 상태는 작업 성공 여부와 별개다. 최근 성공 결과와 최근 시도를 따로 표시한다.

동일 기사 URL은 같은 수집 안에서 통합하고 발견 검색어들을 남긴다. 다른 날짜의 본문·지표 변화까지 덮어쓰지는 않는다. 자산은 해시로 중복 저장을 줄이되 다른 프로젝트가 참조하는 파일을 삭제하지 않는다.

## 7. 수집 비용과 재시작 처리

- 실행 전 검색어·페이지·계정 수, 소스별 최대 건수, 무료/유료 여부, 원본 저장 옵션을 보여준다. 실제 요금을 모르면 금액을 만들어내지 않고 `요금 확인 필요`로 표시한다.
- 현재 24시간 캐시를 자료 종류와 실제 요청 조건 단위로 재사용한다. 다른 자료를 추가해도 기존 자료를 다시 호출하지 않는다. 확인 표시 수정은 수집 캐시를 무효화하지 않는다.
- `새로 수집`은 캐시 사용과 구분한다. 다운로드·이력 복원·파일 재생성은 수집 API를 호출하지 않는다.
- 유료 기능은 기본 ON. 키 누락 또는 확인된 인증/잔액 부족일 때 정확히 **토큰 부족. 개발자에게 문의해주세요**를 표시한다. 네트워크 오류·속도 제한은 별도 설명한다.
- 실행은 소규모 순차 처리부터 시작하고 작업별 완료를 저장한다. 재시작 후 실행 중이었던 작업은 중단으로 표시하고 완료 항목은 유지한다.
- 유료 요청 전송 후 응답 저장 전에 중단된 경우 외부 작업 ID로 확인한다. 확인 불가 시 과금 여부 불명으로 표시하고 자동 재호출하지 않는다.
- 무료 호스팅의 상시 백그라운드 실행을 전제로 하지 않는다. 예약 수집·24시간 감시·별도 작업 서버는 이번 MVP에서 제외한다.

## 8. 자료 확인과 다운로드

수집 체크는 새 요청 대상, 포함/제외는 관련성 상태, 다운로드 체크는 이번 파일에 넣을 대상이다. 세 값을 분리한다. 필터는 표시만 바꾸며 `현재 필터 결과 선택`을 눌러야 내보낼 목록이 변경된다.

기본 다운로드 후보는 포함 자료이며, 확인 필요 자료는 별도 선택한다. 제외 자료는 기본 제외하고 전체 보관용 내보내기에서만 명시적으로 포함할 수 있게 한다. 화면과 파일은 같은 선택 목록을 사용한다.

기본값은 자료 종류별 최근 성공 결과다. 과거 버전을 선택할 수 있고 서로 다른 수집 날짜가 섞이면 생성 전과 파일에 표시한다. 같은 종류의 여러 시점을 비교 출력할 때도 날짜를 보존한다.

- **Excel**: 수집 조건·출처·제한은 필수. 선택 자료 목록과 해당 종류의 상세 시트만 생성한다. 검색 추이를 선택하면 월별·연도별 요약을 포함한다. 광고가 없으면 광고 시트를 만들지 않는다.
- **HTML**: 선택 자료의 요약 표·원문 링크·가능한 미리보기·누락 이유. AI 요약은 선택 시에만 별도 구분한다.
- **ZIP**: HTML·Excel·구조화 결과·선택 원본·구성 명세. 프로젝트 복원용 백업 ZIP과 용도를 구분한다.

기존 11개 고정 시트에서 조건부 시트로 바꾸므로 PRD 내보내기 계약도 함께 갱신한다. 생성한 구성 명세는 선택 변경과 무관하게 보존한다. 원본이 만료되면 같은 구성의 재생성은 가능해도 과거 파일과 완전히 같지는 않을 수 있으므로 새 생성 버전과 누락을 표시한다.

## 9. 저장 상한과 복원 프로세스

다음 수치는 **승인용 초기 기본값**이다. 실제 데이터 크기 측정 후 조정할 수 있도록 설정으로 분리한다.

| 대상 | 개인 PC | 무료 클라우드 |
|---|---|---|
| DB 운영 예산 | 500MB | 300MB |
| 원본·산출물·임시 파일 총예산 | 5GB | 영구 파일 750MB, 임시 파일 별도 제한 |
| 결과 상세 | 프로젝트·자료 종류별 최근 성공 5회, 최근 성공 1회 보호 | 동일 |
| 원본 | 기본 30일, 보관 지정 가능하나 예산에 포함 | 동일, 용량 도달 시 더 일찍 정리될 수 있음을 안내 |
| 생성 다운로드 파일 | 7일 | 24시간 |
| 요청 캐시 | 24시간, 만료 후 정리 | 동일 |
| 실행/다운로드 상세 이벤트 | 12개월 | 동일 |

프로젝트 기본정보와 최근 성공 결과는 자동 삭제하지 않는다. 오래된 실행은 상세 결과 만료 후 날짜·종류·상태만 남기되 이 메타데이터도 12개월 정책과 DB 예산을 적용한다. 프로젝트별 상세 이력 무제한 보관을 약속하지 않는다. 보호 자료만으로 상한에 도달하면 새 저장을 멈추고 백업·삭제·상한 변경을 안내한다.

예산 80%에서 경고, 90%에서 정리 후보를 표시한다. 만료 산출물→만료 캐시/미참조 임시 파일→보관 기간이 지난 원본→보관 개수를 넘긴 결과 순으로 정리한다. 실행 전 예상 저장 여유를 확인하고 저장 중에도 제한한다. 참조 중인 파일·진행 중인 파일은 정리 대상에서 제외한다. DB 크기는 인덱스와 캐시를 포함해서 측정하며 정리 후 실제 공간 회수도 확인한다.

### 복원 시 사용자가 보는 흐름

1. 프로젝트 이력에서 날짜를 선택한다.
2. 저장된 입력과 결과를 읽는다. API는 호출하지 않는다.
3. 보유 상태에 따라 `결과·원본 모두 있음 / 결과만 있음 / 이력만 있음`을 표시한다.
4. 결과가 있으면 화면 복원과 파일 재생성이 가능하다. 원본이 없으면 원문 링크와 만료 표시를 포함한다.
5. 이력만 남았다면 당시 자료는 복원할 수 없다. `백업 가져오기` 또는 `현재 기준 새로 수집`을 제공한다.
6. 새로 수집은 과거 복원이 아니라 새로운 시점의 조사이며 비용이 생길 수 있다.

### 백업과 가져오기

프로젝트별 입력·결과·확인 상태·다운로드 구성·보유 원본을 ZIP으로 내보낸다. 스키마 버전·파일 목록·크기·해시를 포함하며 API 키는 제외한다. 다운로드를 눌렀다는 사실만으로 외부 백업이 완료됐다고 판정하지 않는다.

가져오기는 파일 손상·버전·해시·용량·압축 경로를 검증하고, 내용을 미리 보여준 뒤 기본적으로 새 프로젝트로 복원한다. 부분 실패는 롤백하고 기존 프로젝트를 덮어쓰지 않는다. 자동 클라우드 백업이나 영구 복구를 가정하지 않는다. 클라우드 단일 파일 제한을 고려해 큰 백업은 명세와 번호가 있는 여러 패키지로 나누며, 필요한 패키지 누락을 검사한다.

Vercel은 현재 [WebSocket 지원 문서](https://vercel.com/docs/functions/websockets)가 있으므로 “WebSocket 미지원이라 불가능”으로 판단하지 않는다. 다만 지원 사실이 현재 Streamlit·브라우저·장시간 작업 구조의 직접 배포 가능성을 보장하지는 않는다. 이번에는 프런트엔드 전면 재작성과 별도 수집 서버 도입 비용을 피하는 쪽을 권한다.

권장 클라우드 구성은 Streamlit 앱 + Supabase PostgreSQL(프로젝트·이력·결과) + 비공개 Storage(원본·산출물)다. 무료 DB 500MB·파일 1GB·파일당 업로드 50MB·비활성 프로젝트 중지 조건이 있으므로 앱 예산을 더 작게 잡는다. 대형 파일은 패키지당 40MB를 목표로 나누고 전송량도 관리한다. [Supabase 공식 요금·제한](https://supabase.com/pricing)

Streamlit 서버의 생성 파일은 지속성을 가정할 수 없으므로 SQLite와 원본을 서버 디스크에만 저장하지 않는다. 로컬은 SQLite/폴더, 클라우드는 PostgreSQL/비공개 Storage를 공통 저장 인터페이스 뒤에서 사용한다. 클라우드와 PC 간 실시간 양방향 동기화는 MVP에서 제외하고 백업 가져오기로 이전한다. [Streamlit 생성 파일 지속성 안내](https://docs.streamlit.io/develop/concepts/configuration/serving-static-files)

클라우드는 본인만 접근 가능한 비공개 앱으로 설정하고 실제 비로그인 차단을 검증한다. 데이터 버킷은 공개하지 않으며 다운로드는 짧은 만료 링크 또는 인증된 앱 경유로 제공한다. 서버용 비밀키를 브라우저·로그·백업에 넣지 않는다. 로컬의 127.0.0.1 기본값은 유지하고 클라우드 실행 설정에서만 호스트·포트를 분리한다.

무료 환경에서 검증할 필수 항목은 Linux 브라우저 설치, 홈페이지 캡처, 네이버 화면 접근, 메모리, 요청 시간, 재시작 후 자료 보존, 휴면 후 재개, 다운로드 권한이다. 실패하면 해당 기능을 완료로 표시하지 않는다. 로컬 전체 기능을 유지하면서 대체 배포안을 보고하고, 유료 전환이나 전면 재작성은 다시 확인한다.

### 기존 데이터 이전

기존 세션 하나를 프로젝트 하나로 변환하는 것을 기본으로 하고 같은 브랜드라는 이유만으로 자동 병합하지 않는다. 기존 run의 parts를 새 자료 종류에 매핑하되 원본 v2는 전환 검증 동안 읽기 가능하게 유지한다. 기록되지 않은 입력·원본·수집 조건은 추정하지 않고 `기록 없음`으로 표시한다.

이전 전 건수·파일 존재·총용량을 보고하고, 반복 실행해도 중복 생성되지 않는 이전 절차를 사용한다. 오류 시 기존 버전으로 돌아갈 수 있게 백업한다. 이전 후 기존 이력·자료 수·다운로드 연결을 비교한다. 중복 보관 중인 구 데이터도 저장 예산에 포함하고 검증·백업 확인 전 삭제하지 않는다.

## 12. 최종 수용 시나리오

1. 한샘 프로젝트에서 뉴스만 수집하면 다른 API 호출 없이 뉴스만 저장된다.
2. 같은 프로젝트에서 추이·공식 페이지를 추가해도 뉴스가 다시 수집되지 않는다.
3. 수집 완료 뉴스의 체크를 해제해도 과거 뉴스가 남고, 새로 수집하면 별도 시점이 생긴다.
4. 검색어를 수정해도 이전 실행 입력은 바뀌지 않는다. 다른 한샘 프로젝트와 자료가 섞이지 않는다.
5. 같은 뉴스가 여러 검색어에서 나와도 중복 행 대신 발견 검색어가 보존된다.
6. 자료 1건을 제외하면 기본 Excel/HTML/ZIP 모두에서 빠지고 출처·선택 수가 화면과 맞는다.
7. 최신 수집 실패가 이전 성공 결과를 가리지 않는다. 0건·설정 필요·실패가 구분된다.
8. 36개월 누락·동률·`<10`·상대지수 조건을 올바르게 표시한다.
9. 유료 기본 ON과 키 누락 안내를 확인하되 실 유료 API는 승인 전 호출하지 않는다.
10. 앱 재시작 후 이력·입력·결과가 복원되고 중단 작업은 무조건 재실행되지 않는다.
11. 다운로드 파일만 만료되면 API 없이 재생성된다. 원본/결과 만료 시 복원 한계가 정확하다.
12. 용량 상한·공유 원본·손상 백업·중복 가져오기·큰 패키지·악성 압축 경로를 안전하게 처리한다.
13. 클라우드 재배포 후 자료가 남고, 비로그인 이용자는 화면과 원본에 접근할 수 없다.
14. pytest tests/test_smoke.py -v와 변경 관련 테스트, Streamlit 정상 기동, Home/프로젝트/다운로드의 실제 브라우저 흐름을 확인한다. SAMPLE 표시는 계속 명확해야 한다.

한샘과 제공받은 메리츠 TM 채용 페이지를 무료 실수집 수용 사례로 사용한다. 사이트 차단이나 제공 필드 누락은 실패 이유로 기록하고 임의 데이터로 대체하지 않는다. 실 Meta/Instagram/Gemini 검증은 별도 비용 승인 후 수행한다.

## 13. 최종 확인할 사항

계획 승인 시 기본 적용할 항목은 프로젝트형 화면, 8개 독립 수집, 선택 다운로드, 최근 5회 결과·30일 원본 정책, 로컬 우선 및 무료 클라우드 검증이다. 보관 기간과 예산은 특히 검토가 필요하다.

실제 배포 단계에서는 다음 정보를 확인한다. 계획서 작성이나 로컬 구현을 위해 지금 비밀키를 전달할 필요는 없다.

- Streamlit Community Cloud 비공개 앱과 Supabase Free 사용 가능 여부 및 계정 연결.
- 클라우드에도 본인만 접근한다는 범위와 로그인 계정.
- 기존 PC 데이터를 클라우드로 옮길 프로젝트 범위.
- 외부 API의 서버 환경 사용 제한·할당량과 필요한 설정 값. 키는 비밀 설정에 직접 입력.
- 유료 실검증을 진행할 때만 대상·호출 한도·비용 상한 별도 확인.

무료 배포 검증이 실패해도 유료 플랜으로 자동 전환하지 않는다. 최종 승인 전에는 본 계획 파일 외 제품 코드나 운영 데이터를 변경하지 않는다.
